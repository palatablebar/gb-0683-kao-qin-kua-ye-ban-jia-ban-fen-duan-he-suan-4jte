# 夜班工时与工资

班次属于shift_day；计划结束时间不大于开始时间时跨到次日。打卡是带偏移的时间，先存UTC，再用Asia/Shanghai拆分实际日历日。休息区间按夜班日期归属处理，先从实际工作区间扣除。单班最多18小时，打卡须为整分钟。缺IN或OUT整班隔离，不猜补卡；补卡只能作为显式参数提交（见下）。

## 计价口径裁决

工资倍率**按实际日历日分段**计算（默认 `pricing_basis=calendar_day`）：跨夜班以午夜切段，每段按所在日历日判断法定假日、周末与工作日，段上同时保留 `shift_day` 与 `shift_id`，工资证据仍能对应回原班次。整班套用归属日费率只作为对比口径保留（`pricing_basis=shift_day`），不用于结算。同一员工同一实际日历日的两段工作共用 8 小时正常工时额度，跨班片段也共享。

按实际日历日判断法定假日、周末，法定假日优先3倍、周末2倍、工作日8小时内1倍、超过8小时1.5倍；正常分钟按同员工同日累计，跨班片段共享阈值。参数holidays可传日期列表，默认仅2026-10-01。金额按片段Decimal计算到分，paid为实发工资，差额为应发减实发。此规则用于样例计算，不替代当地劳动法规。

## 补卡与变更

补卡、休息、计划班次与时薪变更通过 `parameters.corrections` 列表显式提交，每条至少包含 `employee` 与 `shift_day`，并至少带一个变更字段：

| 字段 | 含义 |
|---|---|
| `punch` + `at` | 补进/离场打卡；`at` 必须带偏移，缺少打卡的一侧按另一侧生成 `CORR-` 副本 |
| `shift_start` / `shift_end` / `break_start` / `break_end` | 计划班次与休息区间，整班两侧同步生效 |
| `hourly_rate` | 时薪 |
| `reason` | 补卡原因，缺省为“补卡” |

- 变更只作用于配对后的班次副本，原始采信行（`rows`、`_raw`）保持不变，行数对账不受影响。
- 同一班次同一字段被两条取值不同的补卡命中时，后一条记 `CONSTRAINT` 拒绝，不静默覆盖。
- 目标员工/归属日无班次记 `REFERENCE`；字段或格式非法记 `RANGE`/`DATE`/`CORRECTION`。
- 被拒绝的补卡同样随批次留痕，但不进入行数对账。

## 重算、修订与复核

- 同源输入（输入字节 + 参数 + 规则版本）复用同一批次；重复提交只更新“最近查看”，不覆盖原始结果与已存补卡原件。
- 补卡、休息、假期或计价口径变更通过 `POST /api/runs/<id>/recalculate`（口径快捷入口 `POST /api/runs/<id>/basis`）。
- 每次结果变化追加一条修订（`run_revisions`），记录口径、指纹与时间；`GET /api/runs/<id>/revisions` 可查。结论完全相同的重算不新增修订，也不打断已完成的复核。
- 结论变化后复核版本递增并回到“待复核”；复核决定只追加到 `review_log`，不覆盖历史。
- 正常工时额度由同一条计算路径按片段重算，重跑不会重复累计。

## 失败恢复

- 重算候选先在内存完成，对账不平、封存未通过或参数非法时返回 409/422，生效修订与补卡原件保持原样。
- 页面切换口径失败时原样恢复上一版工作表内容并提示“已恢复旧版结果”。
- 导出按 `?revision=N` 取任意历史修订；指定修订不可用时回退到当前生效版本，并在 `X-Archive-Fallback: active` 标出，不会导出半成品。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

同一员工/归属日/方向的最高版本若有时刻、时薪、班次、休息或实发金额冲突，则整班隔离；选中IN与OUT的时薪、班次起止与休息起止也必须完全一致。
